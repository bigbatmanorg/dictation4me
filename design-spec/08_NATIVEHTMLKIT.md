# NativeHTMLKit public API usage and feature gates

**Reviewed public release baseline, 2026-11-16:** NativeHTMLKit Core 1.0.3, Python SDK 0.1.2, Python UI 0.1.1. Confirm latest versions when implementing; these are documented release numbers, not lifetime pins. Source links in `docs/15_SOURCES.md`.

## Dependency discipline

`dictation4me app UI → nativehtmlkit_ui (optional) → public nativehtmlkit Python SDK → Core host`. App UI may call **public SDK** directly, especially Document and Window methods. It must never import Core source, host RPC protocol, CLI implementation, Rust FFI, private types or bundled-host internals. Any missing Core primitive needs a reproducer and an upstream public-SDK-compatible request; don't patch it secretly from the app.

## Supported essentials and gaps

| Need | Public API path / limitation | Implementation |
|---|---|---|
| Open native windows, plain CSS | `Application.start`, `open_html/open_file`, local CSS assets | Supported; mount one main notebook window |
| `<textarea>` Markdown editing | `Document.get_value`, `set_value`, `on('input')`, `control_selection`, `replace_control_range` | Use **SDK** directly; UI 0.1.1 does not provide 2-way bound textarea |
| Basic UI components | `nativehtmlkit_ui` State/UI cards/buttons/inputs | Optional for stable UI sections; workaround known input column height defect; custom DOM appropriate |
| Dynamic note list | UI `text_list` only, no per-row buttons or virtualization | Custom escaped HTML & delegated DOM events using SDK; paginate on service side |
| Modal/popup | SDK HTML `<dialog>` and popover operations | Good for confirmations; UI library lacks wrappers |
| Clipboard in GUI | `Application.clipboard_text` / `set_clipboard_text` | Available when GUI/desktop active; resident uses its own OS adapter |
| Multiple windows | `Application.open_html`, `create_window` | Main + review only if lifecycle stable; avoid repeated rapid create/dispose in UI 0.1.1 |
| Audio playback | No native Core `<audio>` playback | Python `sounddevice` playback worker, custom controls in UI; no embedded media element |
| Chart / waveform | SDK LiveBitmap RGBA8 | Optional later; not needed v1, avoid high-frequency GUI protocol updates |
| Rich-text editor | Core rejects `contenteditable=true` | Markdown source in textarea; sanitized read-only preview |
| Hidden/always-on-top window on Wayland | No guaranteed existing-window show/focus in public SDK | Use no-focus notification + regular notebook; never promise overlay in v1 |
| Tray | No Core tray capability | OS adapter separate from NativeHTMLKit |
| Native file dialog | SDK `Window.open_files/save_file/choose_folder` | Use for export/backup/import |
| Native desktop keyboard shortcut | Current SDK handles in-window keys, not global shortcut ownership | OS adapters, keep in resident process |

## SDK lifecycle correctness

`Application.start()` launcher re-executes backend when connected to host. All actual database/process/audio initialization must be **after** `start()` returns in host-backend role. Better: keep GUI free of direct DB/recorder setup, calling already-running service. Run `app.run()` on UI event thread; marshal async service replies to UI owner safely. GUI `on_shutdown` cancels subscriptions and saves pending draft (with bounded service ACK), not service shutdown. In NativeHTMLKit UI, use `ui.post()` for state changes generated by workers. Test stale Document/Window handles and full cleanup.

## Rendering safety

Core rejects `<script>`, `<iframe>`, arbitrary event attributes and rich text contenteditable; no JS. Notes and model text must always be displayed with `set_text`/`set_value` or escaped via `html.escape` before custom HTML insertion. A Markdown preview renderer must sanitize allowed tags, attributes and URL schemes **before** `replace_html`; never blindly render model-produced HTML. Local asset root only; no loading remote CSS/fonts/assets or executing links.

## Avoid accidental scope expansion

If editor performance is inadequate, first profile Document operations, batching, payload size and note paging. Never build a replacement UI framework or add a generic virtual DOM in the app. If a public primitive is missing, record exact call/input/expected/observed, minimal repro and platform and propose upstream change only when no safe app-level alternative exists.

## Baseline regressions to track

- UI 0.1.1 input column `flex-basis` can produce oversized 200px fields. Use custom CSS rule or lay out fields in rows/cards until upstream fix.
- Python UI `Computed` may race on concurrent state mutations; serialize updates through UI owner.
- Repeated mount/dispose of UI windows may accumulate callbacks; prefer reusing primary window.
- Real screen-reader/IME/scaling qualification incomplete; run manual acceptance on exact release binary.
- Current Linux wheel's glibc **2.39+** floor needs explicit `doctor` check and packaging documentation.
