# UX and screen contracts

## Aesthetic direction

NativeHTMLKit, no browser. Compact, mature desktop proportions: slate-blue background (#101927), slightly lighter sidebars (#172437), cobalt primary (#497dd6), readable text (#e3ebfa), low-contrast hairline borders. Density default **compact**, optional comfortable. Do not ship huge buttons, 200px form gaps or a white/black-only palette. Respect OS scale and reduced motion. The styles are an implementation target, not a promise of pixel parity across OS.

## Notebook main window

**Three-pane desktop width ≥1050 logical px:**

- Left 160–200px: All Notes / Recent / Pinned / Voice / Trash / Recovery; folders; Settings. Keyboard navigation.
- Middle 220–280px: search bar, sort/filter, virtualized or paginated list of note previews. Selected note highlighted, item actions accessible by keyboard.
- Right flexible editor: title; tags/folder/status; Markdown textarea; bottom word count, saved status; top Record, Transform, Copy and More actions. Collapsible right AI inspector only when requested; no always-open chatbot.

**Narrower widths:** at 700–1049 hide inspector; at <700 switch to notes list/editor navigation, not four tiny columns. Observe live resize. Keep minimum window usable at 640×440; when OS allows smaller, scroll instead of overflow.

## Notebook interactions

- New note: creates blank note + draft immediately; focus title or body as configured. Empty notes are not garbage-collected before user has finished a session.
- Autosave: small 'Saving...' then 'Saved locally' status; failures persistent and actionable. Never show 'Saved' before SQLite commit acknowledgement.
- Note list: keyboard up/down and Enter, search with Ctrl+K, create Ctrl+N, focus editor Ctrl+E, AI palette Ctrl+Shift+P, record Ctrl+R **when notebook focused**. Platform-specific menu shortcuts can be remapped; check global conflicts.
- Markdown source in `<textarea>`; Shift+Enter, Tab, selection, IME tested. Optional read-only Preview tab; do not use `contenteditable`.
- Delete moves to Trash with Restore. Permanent deletion demands confirmation. Drag-and-drop reorder deferred; use folder picker and tags.
- Selection AI: snapshot exact selected text and source revision hash; show in proposal preview what range is affected; accept only after rechecking edit sequence. If note changed, offer *New alternative* rather than silently replacing.
- AI preset palette: filter, choose, Run, Cancel, Compare before/after, Accept as current, Save alternative, New note, Copy, Discard. Prompt editor not automatically shown.
- Versions: show accepted revisions and audio/transcript origins; AI proposals separately until accepted/discarded. Restore creates a **new current revision** based on old content, preserving history.

## Quick capture: no focus theft

- Default UI is native notification + optional start/stop sound + tray status. **No NativeHTMLKit popover assumed on KDE Wayland.** Never open main GUI on first shortcut.
- Notification states: 'Recording · 00:18', 'Transcribing', 'Ready — press shortcut to copy/deliver', 'Copied; paste shortcut sent (unverified)', 'Copied only', 'Needs attention: see Recovery'. On desktops that don't support live update notifications, show bounded event notifications instead.
- `dictation4me quick-review` opens normal notebook-like review window explicitly, not as a side effect of recording. This UI can edit current output, choose AI preset, Copy, Deliver, or Save as Note.
- A deliberate *Save as Note* action promotes temporary capture into permanent notebook, retaining original transcript and selected output. If quick audio has already been deleted by retention policy, the note has the transcript but no playable recording; show this honestly.
- If user changes clipboard after result is copied but before injection, skip injection. If user moves focus, state the risk or skip based on platform/setting.
- If delivery is uncertain, remain recoverable and allow explicit Copy Again / Paste Again; never auto-repeat or silently close result.

## Settings screen: sections

**General:** theme, density, start at login, default mode, audio indicator, app data path (read-only after init).

**Audio:** input device and level test (local only), silence/maximum duration, format, retention per mode, playback test. Test starts/stops explicitly.

**Transcription:** STT base URL/model/key source, request type/basic vs model-specific, language hints, connection/sample test, timeouts and limits; provider warning when remote.

**AI:** Chat Completions base URL/model/key, max tokens/timeouts, per-mode default preset, preset editor, result behavior, sample transformation test; user must see which note content is sent.

**Shortcuts & output:** shortcut registration status/conflicts, manual vs auto-deliver, per-platform capability, clipboard-only, paste shortcut (Ctrl+V / Ctrl+Shift+V) and controlled test; expert-only Wayland injection setup.

**Storage/privacy:** quick retention, audio retention, export/backup/restore, trash purge, keyring status, log location and clear history.

**Diagnostics:** capabilities and versions, consent state, service PID/session, no secrets or transcript content.

## Accessibility and states

- Every control has accessible label and visible keyboard focus. Tabbable controls have useful order and shortcuts can be disabled/rebound.
- UI must render: empty notebook, no microphone, unconfigured STT, unavailable LLM, service unreachable, request timeout, canceled request, blocked clipboard, unavailable native notification, locked keyring, invalid FTS, insufficient disk.
- Use non-color status labels with text; colors are supplemental. Do not auto-delete user text on request failure.

## Prototype

`design/prototype.html` previews layout and two capture states in a normal browser for **design review only**. Production UI is rendered by NativeHTMLKit using supported HTML/CSS and Python callbacks. No JS is to be shipped in the application.
