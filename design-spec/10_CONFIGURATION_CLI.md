# Configuration, CLI, installation and paths

## Package / runtime

Python >=3.12 (pin tested minor versions on Linux/Windows), `uv` project + `uv.lock`, `httpx`, `sounddevice`, appropriate audio conversions only as needed, `keyring` optionally when supported; NativeHTMLKit SDK and optional UI library for GUI. No Node, JS, Tk, Qt, GPU inference dependency, external DB, HTTP listener or web runtime. `dictation4me` remains package and CLI name. Installer must check NativeHTMLKit Linux glibc compatibility.

## Config & secrets

Use a small TOML file generated by `init` from `spec/config.example.toml`; no plaintext secrets. Strict validation: absolute paths only where required, timeout and length bounds, shortcut conflicts, trusted URLs, retention choices. Environment overrides use explicit documented prefix (`DICTATION4ME_*`) without broad wildcard merging. Credential entries reference keyring service/name or environment variable **name**. CLI `config validate` prints normalized safe values without key contents.

Suggested user dirs (use platform conventions / `platformdirs` when verified):

| OS | Config | Data | State |
|---|---|---|---|
| Linux | `~/.config/dictation4me` | `~/.local/share/dictation4me` | `~/.local/state/dictation4me` + private runtime endpoint |
| Windows | `%APPDATA%\Dictation4me` | `%LOCALAPPDATA%\Dictation4me\data` | `%LOCALAPPDATA%\Dictation4me\state` |

A `DICTATION4ME_HOME` dev/test override redirects all paths and **must not** touch real installed launchers or other user's paths without explicit flag. Use restrictive ownership/permissions; never place auth token in world-readable temp.

## Public CLI (proposed normative commands)

```text
dictation4me init [--dry-run] [--autostart|--no-autostart]
dictation4me gui
dictation4me quick-review
dictation4me toggle                      # safe external KDE shortcut fallback
dictation4me cancel                      # explicit current capture cancellation
dictation4me copy-last
dictation4me paste-last                   # explicit retry; duplication warning
dictation4me service start|stop|status|restart
dictation4me doctor [--json]
dictation4me devices
dictation4me test microphone|stt|ai|clipboard|paste [--dry-run]
dictation4me config show|validate
dictation4me export --output PATH [--with-audio]
dictation4me backup --output PATH [--with-audio]
dictation4me restore --input PATH --destination PATH
dictation4me recover list|retry|delete ID
dictation4me uninstall [--purge]
```

- `init` idempotent, no admin/sudo by default. Print proposed files and permissions. OS packages/uinput changes require user approval with dry-run and explicit `--enable-...` options, not automatic changes.
- Start Menu/desktop autostart run installed interpreter, not checkout. Onboarding auto-start suggestion may be enabled only after user choice.
- Status and doctor must be usable without GUI or configured provider. `doctor --json` nonsecret schema for agent diagnostics.
- `test paste` requires disposable target and intentional countdown/confirmation; never send synthetic input without explicit command/approval.
- `service stop` completes/marks interrupted captures safely. `uninstall` preserves stored notes/credentials by default and removes launchers; `--purge` requires confirmation and deletes only app-owned paths.
- All mutating CLI commands have clear exit codes. Machine output uses UTF-8 JSON when `--json`, no spurious ANSI status logs.

## Default config example

`spec/config.example.toml` is the authoritative machine-readable example. Runtime flags must not silently override user UI preferences except documented environment override precedence.

## Installation/updates

Use `uv tool install git+https://github.com/bigbatmanorg/dictation4me.git` after publication or `uv tool install .` from checkout. Agent must validate prebuild/wheels for Windows and Linux, native DLL/host packaging, microphone permissions, and independent CLI/GUI entry points. Real deployment may need PortAudio or Linux clipboard tools; `doctor` recommends only what is missing. Pin lockfile once dependencies are resolved by the implementation agent.
